Asistente de instalacion de GTE

Captura aqui los datos de la computadora nueva. Al final se genera instalar-gte.ps1, un instalador que se corre como administrador en esa maquina y deja GTE funcionando: scripts de base de datos, servicio de Windows, variables de entorno, puerto, firewall y el usuario administrador con el que se entra la primera vez.

Todo se procesa en esta pagina. No se envia nada por red ni queda guardado en ningun lado.

2 Conexion a la base de datos

La base bdsGTE ya debe existir (Paso 1 del manual de instalacion). El login con el que la aplicacion se conecta a diario se puede crear aqui mismo, o usar uno que ya tengas -- tu decides.

Nombre de instancia, o servidor,1433 si usa otro puerto.
Con el que la aplicacion se conecta a diario (por defecto svc_gte, puede ser cualquier otro, incluido sa).
Si el checkbox de abajo esta marcado, esta es la contrasena con la que el instalador va a crear la cuenta -- no hace falta que exista todavia. Si esta desmarcado, tiene que ser exactamente la contrasena que esa cuenta ya tiene.
El instalador lo crea con la contrasena de arriba y le da permisos minimos en bdsGTE (lectura/escritura + ejecutar los procedimientos del motor propio -- nunca db_owner). Si ya existe, no lo toca. Desmarca esto si el login ya existe con sus permisos y solo quieres que el instalador se conecte con el.

3 Usuario administrador de GTE

Con esta cuenta se entra la primera vez. Si ya la diste de alta al correr los scripts a mano, el instalador solo le pone la contrasena que captures aqui; si no existe todavia, la crea.

Es lo que se escribe en la pantalla de login (columna Dominio).
Minimo 8 caracteres (misma regla que valida la API).
Util si vas a entregarle la contrasena a otra persona: GTE le exige cambiarla al entrar.
Como queda hasheada: el instalador da de alta la cuenta con la contrasena temporal del repositorio y despues, ya con el servicio arriba, entra a la API y la cambia por la que capturaste aqui. Asi la contrasena se hashea con la misma version de BCrypt que usa GTE, sin instalar el SDK de .NET en la maquina nueva.

4 Manejo de las contrasenas en el script

Decide si el archivo .ps1 lleva las contrasenas escritas o las pide al ejecutarse.

El .ps1 no contiene ninguna contrasena: las pide en consola al arrancar. Puedes guardarlo o mandarlo por correo sin riesgo.
Corre sin intervencion, pero el archivo queda con las contrasenas en texto plano.
Cuidado: el archivo generado va a contener la contrasena de SQL y la del administrador en texto plano. Borralo de la maquina en cuanto termine la instalacion y no lo subas al repositorio ni lo mandes por correo o chat.

5 Instalador generado

Se actualiza solo conforme llenas los datos.

Faltan datos por capturar.

Que va a hacer en la maquina nueva:

  1. Verificar permisos de administrador y el runtime de .NET 8
  2. Crear el login de conexion a bdsGTE (si no existia) con permisos minimos
  3. Dar de alta el usuario administrador (si no existia) con rol Administrador
  4. Copiar la aplicacion publicada a la carpeta de instalacion
  5. Fijar el puerto en appsettings.Production.json
  6. Crear el servicio de Windows
  7. Registrar las variables de entorno (ambiente, cadena de conexion y clave JWT nueva)
  8. Abrir el puerto en el firewall
  9. Arrancar el servicio y verificar /health
  10. Fijar la contrasena real del administrador contra la API
Para correrlo en la maquina nueva, en PowerShell como administrador:
powershell -ExecutionPolicy Bypass -File .\instalar-gte.ps1
